# Promises belong to wallets, not GitHub users

The pay page has no GitHub sign-in. Anyone with the link can make a promise for any first-timer, and a kept promise refunds the wallet that paid. We picked this over GitHub OAuth on the pay page because it saves a second login flow, it means a refund can never go to the wrong person, and it gives co-signing for free: an existing contributor vouches for a newcomer by paying their link. The cost is that the app can't say who vouched, so there is no `/cosign` command and the bot can't credit co-signers by name. Adding GitHub identity later means storing a GitHub user ID on each promise.
