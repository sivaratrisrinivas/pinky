# The app holds the arbiter key in v1

The Pinky GitHub App holds one arbiter keypair and signs every verdict for a maintainer who comments `/accept`, `/spam` or closes the issue. The program trusts that key, so a leaked key could settle any open promise. We accepted that because asking maintainers to sign with their own wallet adds a wallet flow for every maintainer and wouldn't fit the hackathon timeline. The limit is that refunds go only to the promiser's wallet and broken promises only to the maintainer wallet, so the arbiter can pick an outcome but can't send money anywhere else. In v2, the maintainer's own wallet signs.
